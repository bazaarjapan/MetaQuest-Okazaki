# 生徒ログイン情報の一括再発行（管理者用）

通常の授業は、先生のGoogleログインと生徒のID・パスワードだけで始められます。作品と受け付けた位置は自動保存され、復元ポイントを手動で作る必要はありません。この手順は、全生徒の認証情報を更新する明示的な依頼があるときだけ使います。

`scripts/reset-student-logins.mjs` は本番D1の発行済み生徒を対象に、新しいIDとパスワードを作ります。`user_id`・生徒枠・名前・作品・所属は維持します。先生の認証情報は変更しません。

1. ローカルWranglerが正しいCloudflareアカウントへ認証済みであることを確認します。
2. リポジトリ外の、新規の専用フォルダーを指定して計画を作ります。次は例です。

   ```powershell
   node scripts/reset-student-logins.mjs --output 'C:\Users\YOUR_NAME\Documents\student-logins-YYYYMMDD'
   ```

   この段階では本番の認証情報を変更しません。Windowsではフォルダーと既存の既知ファイルのDACLを現在の利用者とSYSTEMだけに置き換えて検証します。他のファイルがあるフォルダーやリンクは拒否します。

3. 同じフォルダーを指定して適用します。

   ```powershell
   node scripts/reset-student-logins.mjs --output 'C:\Users\YOUR_NAME\Documents\student-logins-YYYYMMDD' --apply
   ```

   更新は全対象の旧ID・旧ハッシュ・枠が一致するときだけ行い、学生セッションの失効を同じ原子的UPDATEのトリガーに含めます。更新後のID・ハッシュ・枠、学生セッション数、ユーザー・作品原本・所属・先生数を検査します。古いWebSocketも次回メッセージの認証確認で停止します。

4. 専用フォルダー内の `verification.json` を確認し、`生徒ログイン配布用.csv` から各生徒に本人の行だけを安全に渡します。旧ID・パスワードは使えません。

CSVと`private-plan.json`は秘密情報です。Git、公開サイト、Issue、PRやクラス全体へ貼り付けないでください。端末内のアクセス制限は、パスワード付き暗号化ファイルの代わりではありません。

結果不明や途中失敗では、フォルダーを変えず同じコマンドで再確認します。計画を再利用し、すでに同じ情報へ更新済みなら再発行しません。適用前に名簿が変わった場合は更新せず停止します。新規の計画を作る前に、既存計画の適用結果を調べてください。
